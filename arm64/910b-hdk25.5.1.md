# 昇腾 910B 64 GB 学生训练镜像

适用环境为 ARM64 Linux、昇腾 910B 64 GB 和 Ascend HDK 25.5.1。镜像包含 CANN 9.0.0、910B 算子、Python 3.11、PyTorch 2.10.0、TorchNPU 2.10.0 与 LLaMA-Factory 0.9.3。容器运行时禁用在线依赖和模型下载。学生基模读取现场共享目录中的本地权重。[昇腾驱动与 CANN 配套](https://www.hiascend.com/document/detail/zh/canncommercial/900/releasenote/release-notes.md) · [TorchNPU 配套表](https://github.com/Ascend/pytorch/blob/master/COMPATIBILITY.en.md)

## 导入和预检

在训练节点确认 `npu-smi info` 能显示设备和驱动版本，Docker 已注册名为 `ascend` 的运行时。将整份离线包拷入现场后，在包目录执行以下命令。`0` 是示例物理卡号，按 `npu-smi` 输出填写，执行前确认相关卡空闲。

```sh
sha256sum -c SHA256SUMS
python3 scripts/load-images.py --bundle .
trainer_image=gcs/distill-trainer:0.9.3-cann9.0.0-torch2.10.0-hdk25.5.1-vl-arm64
python3 scripts/preflight.py --arch arm64 --trainer-only \
  --trainer-image "$trainer_image" --shared-root /storage-root-jfs --npu-devices 0
```

多卡预检使用逗号分隔的物理卡号。脚本检查容器可见设备数量，并逐卡比较 FP16 矩阵运算的前向结果和反向梯度。可加 `--model <基模绝对路径>` 检查本地基模配置与分词器。现场启用前，用平台真实数据跑一条短 LoRA 任务，确认训练日志与权重产出。需要多卡时，再验证单机 HCCL 训练。

## 接入 gcs-distill

在现有 `[executor]` 配置段中更新下面的键。`training_workers` 填已经导入镜像且完成预检的 GCS 节点名。保存配置并重启 `gcs-distill` 后，使用 `/api/v1/runtime` 核对镜像，再从资源页选择现场训练卡。

```toml
training_accelerator = "ascend"
trainer_image = "gcs/distill-trainer:0.9.3-cann9.0.0-torch2.10.0-hdk25.5.1-vl-arm64"
training_workers = "现场训练节点名"
```

## 重建镜像

在 ARM64 构建机预置官方基底与 `arm64/image/trainer-hdk25.5.1-requirements.lock` 所列的 Python 3.11 ARM64 wheels。`build-image.sh` 校验基底镜像 ID 和 LLaMA-Factory 提交，随后在断网构建阶段安装。

```sh
cann=quay.io/ascend/cann
base_digest=sha256:5d90a091e383f46cfe81c1e4589d23326e6baea5d475a6509a6d600d2520019d
docker pull --platform linux/arm64 "$cann@$base_digest"
docker tag "$cann@$base_digest" "$cann:9.0.0-910b-ubuntu22.04-py3.11"
git -C /path/to/LLaMA-Factory archive --format=tar -o /tmp/trainer-source.tar ca75f1edf3cb50343ed1c98605141c3e22075b5f
bash arm64/build-image.sh trainer-hdk25.5.1 /tmp/trainer-source.tar /path/to/wheels
```
